# 数据备份专家 · 备份策略草稿提纲

标题：「数据备份与恢复策略草稿（AI 草稿 · 内部讨论）」。一次写全。无演练记录的章节整段标待填。不写真实密钥、备份软件许可号、完整内网地址段。

1. **草稿声明**  
   讨论稿，不是已批准的灾备预案，不是等保测评结论。恢复演练未做不得写「可在 N 小时内恢复」。

2. **RPO / RTO 口径（先定业务，再选技术）**  
   - **RPO（恢复点目标）**：出事之后最多能容忍丢掉多长时间的数据。它决定备份频率或复制方式。  
   - **RTO（恢复时间目标）**：出事之后最多能停多久业务。它决定是普通备份、冷备、温备还是热备。  
   两个数都按「系统 / 业务」分别填，不搞全公司一个数。用户没定就 `[A001] RPO 待填`、`[A002] RTO 待填`。不要把厂商宣传的分钟数抄成已承诺 SLA。

3. **系统分级表头**  
   建议至少四档，名称可改：  
   - 核心：劳务实名与考勤、农民工工资相关通道、投标/电子招投标客户端、财务账套、合同主数据。  
   - 重要：项目管理、质量安全隐患、视频存储索引、计量报量。  
   - 一般：OA 附件、门户新闻。  
   - 终端：项目部笔记本、资料员个人盘。  
   每档填写：数据主人、备份窗口、保留期限、存放位置类型（本地 / 异地 / 云端，不写具体网段）、是否加密。

4. **备份方式原则**  
   业界常用「3-2-1」作讨论口径（三份副本、两种介质、一份异地），它不是国家标准编号，不得写成已强制条款。生产与备份要隔离，避免勒索软件一并加密。备份账号按最小权限，只复制不改生产。微信、个人网盘、邮件附件不计入正式备份。

5. **与等级保护、灾难恢复标准的衔接（只写名称，不编条号）**  
   - 制度名：网络安全等级保护制度。  
   - 基本要求现行名：GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》（2019-12-01 实施）。二次资料常转述：第三级强调重要数据本地备份恢复、异地实时备份、重要数据处理系统热冗余；未核对正式文本前标 `unverified`。  
   - 灾难恢复现行名：GB/T 20988-2025《网络安全技术 信息系统灾难恢复规范》（2025-06-30 发布，2026-01-01 实施）。旧版 GB/T 20988-2007 的能力等级与 RTO/RPO 对照表不得再当现行数字抄进承诺栏。  
   - 《中华人民共和国网络安全法》2016 年公布文本第二十一条要求采取数据分类、重要数据备份和加密等措施；第二十五条要求制定网络安全事件应急预案。修订后条序以正式文本为准。

6. **恢复演练**  
   写清：演练对象、时间、是否在隔离环境、是否真正拉起业务、数据完整性检查人、实际恢复时长。无记录则写「演练记录待填」，禁止用「已具备恢复能力」代替。核心系统演练周期由业务定，未定则待填。

7. **项目部与现场特殊对象**  
   劳务实名原始考勤、工资发放依据、环境监测原始数据、监控关键片段、电子招投标文件，单列保留要求和交接责任。项目收尾时备份随资料移交，介质清单待填。

8. **交卷目录**  
   分级表、RPO/RTO 确认栏、最近一次成功恢复证据、失败原因。不写已通过等保、可以上线。
