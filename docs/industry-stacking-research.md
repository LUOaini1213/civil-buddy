# 集装箱装载 · 堆码：GitHub / 论文 / 行业怎么做

> 调研日：2026-07-29 · 对照 packing-agent（偏地面铺满、少叠层）

---

## 1. 行业（海运 / CTU）

权威框架：**IMO/ILO/UNECE CTU Code**（货物运输单元装载与加固）：

| 原则 | 行业要求 | 我们现状 |
|------|----------|----------|
| **堆码** | 按箱型承重/标识「最多叠 x 层」；重下轻上 | 有 stackable 字段，3D 少叠 |
| **稳定性** | 支撑面足够、不悬空、防倾倒 | 几何 AABB 贴靠，无支撑面积约束 |
| **重心** | 宜低、居中；前后大致中段 | 有 COG 偏心检查 |
| **加固** | 绑扎、充气袋、木方填缝，**不能数学贴死无间隙** | 无绑扎间隙模型 |
| **装卸** | 开门端顺序、叉车可操作 | 基本不考虑 |
| **利用率** | 在安全前提下提高；**安全优先于极限贴紧** | 偏体积/重量优化 |

**结论（行业）**：允许且鼓励合理多层堆码；「全铺地、不叠高」不是惯例最优，而是算法简化。  
「贴得极紧」现场会留 **绑扎/防移空隙**，与纯 3D-BPP 贴死不同。

## 2. 学术论文（3D Container Loading Problem）

综述（Bortfeldt & Wäscher 等）与后续工作中的 **高频约束**：

| 约束类型 | 含义 | 文献常见做法 |
|----------|------|----------------|
| **Orientation** | 可旋转方向有限 | 禁止随意 6 向 |
| **Stability** | 静态支撑面积 / 动态加速度 | 底层全接触、支撑比阈值 |
| **Stacking / load-bearing** | 下层承重、叠层数上限 | 「Stack no more than x high」 |
| **Weight order** | 重下轻上 / 密度序 | 排序启发式 + 硬约束 |
| **COG / balance** | 重心在柜中心附近区域 | 目标函数或罚项 |
| **Multi-container** | 多柜分配 | 先分柜再柜内 3D |

近年方向（2025–2026）：

- 混合易碎/普通货的 **平衡装载 + 堆码**（Zhang 等）  
- **力学模型嵌入** GRASP 等启发式（Montes-Franco 等，MDPI 2025）  
- 多集装箱 + 重量/重心/动力稳定的 **ILP 模型**（Alonso 等系列）  
- 中文文献：转弯重心、静/动态稳定、多目标（利用率 + 载重 + 重心）

**算法套路（论文共识）**：

1. **构造启发式**：墙/层/塔（wall / layer / tower）— 先建稳定层再叠  
2. **排序**：体积大、重、不可叠的先放  
3. **元启发式 / 混合**：GRASP、遗传、禁忌 + 局部稳定修复  
4. **少做「只铺一层」**：高度方向是主要优化维度之一  

**与我们的差异**：我们接近 **LAFF 地面铺满**；论文更常 **layer/tower 堆叠 + 稳定修复**。

## 3. GitHub / 开源 / 商业软件

| 项目/产品 | 堆码相关 | 备注 |
|-----------|----------|------|
| **skjolber/3d-bin-container-packing** | 3D 矩形装箱、LAFF 变体 | 工业库；堆码/承重靠调用方约束 |
| **DeepPack3D / Online-3D-BPP** | RL/在线 BPP | 偏利用率与序列，稳定约束常简化 |
| **EasyCargo / LoadCargo 类** | 层叠、不可叠、重底、可视化 | 现场装柜软件；有间隙与堆码 UI |
| **Smart Stowage（Gemini 双引擎）** | 启发式 + LLM 软约束 + COG | 强调稳定叙事 |

**开源共性**：  
- 核心是 **几何 NP-hard 3D-BPP**  
- **承重/绑扎/CTU** 多在商业层或调用方规则里  
- 很少「只铺地不叠」当作最优目标

## 4. 对照 packing-agent

| 能力 | 论文/行业 | packing-agent |
|------|-----------|---------------|
| 多层堆码 | 标准能力 | **弱**（混合 30t 几乎 z=0） |
| 重下轻上 | 硬/软约束 | 规划有意图，3D 不保证 |
| 承重/叠层上限 | 常见 | 结构校核 ≠ 3D 叠层 |
| 重心 | 目标/约束 | 有 COG 指标 |
| 绑扎间隙 | 行业必须 | **无** |
| 双利用率/订舱口径 | 少见（偏我们业务） | **强**（领域差异化） |
| 箱→物料追溯 | 业务系统 | **有 content.material_id** |

**我们强在**：钢结构成箱、订舱口径、Agent 闭环。  
**我们弱在**：柜内 **堆码策略与海运稳定惯例**。

## 5. 建议改进优先级（若对齐行业/论文）

| 优先级 | 项 | 依据 | 状态 |
|--------|-----|------|------|
| P0 | **可叠则优先叠层**（stackable + 限高） | 行业多层；论文 layer/tower | ✅ `PackPolicy` + `try_place` |
| P0 | **重底轻上** 进 3D | CTU + 综述 | ✅ 软罚分 + 支撑箱 stackable |
| P1 | **支撑面积/稳定** 简化规则 | 论文 stability | ✅ `support_ratio_min=0.55` |
| P1 | **箱间最小间隙**（绑扎余量 20–50mm） | CTU 加固 | ✅ `clearance_mm` 默认 30 |
| P2 | 力学/GRASP 级优化 | 研究向 | ⚡ 轻量 multi-start（双策略） |

## 6. 一句话

> **GitHub/论文**：3D-CLP = 利用率 + 稳定 + 堆码 + 重心，堆叠是常规不是例外。  
> **行业**：安全堆码与加固优先，允许叠、要求重下轻上，不鼓励无间隙死贴。  
> **我们**：地面铺满型启发式 → 侧视「扁、挤」；要贴近惯例，应补 **可控叠层**，而不是更挤的平面铺满。
