# 岗位交付物：把用户说的话，放进该放的栏位

> 2026-09-20。相关代码：`packing_assistant/post_facts.py`、`scripts/eval_post_content.py`、
> `scripts/test_post_content.py`、`test/benchmarks/post_content/`。

## 1 问题

66 个岗位的 `SKILL.md` 和 `demo/kb/` 知识库是齐的，章节骨架也是齐的。缺的是中间那一步：**把用户这一
句话拆开，放进表格的列里**。

工地上的人是这么打字的：

```
螺纹钢 HRB400 Φ20 本周入库 35 吨，领用 12 吨，盘点差 0.3 吨，仓管员张伟
```

改造前，仓管岗的交付物是这样的：

| 物资 | 入库 | 出库 | 结存 | 备注 |
| --- | --- | --- | --- | --- |
| 帮我写一份仓库收发存台账口径：螺纹钢 HRB400 Φ20 本周 ，领用 12 吨，差 0.3 吨，仓管员张伟 | 35吨 | TBD | TBD | 待填 |

整句话被粘进了「物资」格，「领用 12 吨」原地留在句子里没进「出库」列，张伟不知去向。
两类写法各有各的塌法：

- `expert_turn.py` 一族：按 `；`／换行切块，每块取**一个**数字 → 整句进一格，其余 TBD。
- `post_drafts/*.py` 一族（30 个岗）：只认 `标签：值` 行或 Markdown 表 → 一句连贯的话什么也匹配不上，
  交付物是一张**全 UNSPECIFIED** 的漂亮骨架，连用户原文都没回显。

已有的 `eval_post_scorecard.py` 量的是「该有的栏在不在、占位符留没留住」——上面这两种草稿都能全过。

## 2 量法

`test/benchmarks/post_content/` 是新基准。一条用例 = 一句真人会打的话 + 这句话里的事实 + 每个事实**该进
的栏位**（写成正则备选，描述的是「一份称职的交付物该放哪」，不绑当前实现的列头措辞）。判定见该目录
README。关键是 `misplaced`：值进了短栏位但挂在**别的对象**名下——这比留个 TBD 更糟，所以门禁单独拦它。

每岗三条，覆盖三种写法：整句、分行、以及一句里**两个对象**且缺字段的「messy」——后者专门抓
「甲材料的数被安到乙材料行上」。

```bash
python scripts/eval_post_content.py                  # 按岗位一行
python scripts/eval_post_content.py --post cost -v   # 每个未落位事实一行
python scripts/eval_post_content.py --show cost-02   # 打印该用例的交付物
python scripts/test_post_content.py                  # 门禁：对着 floor.json 卡回退
```

## 3 共用层 `post_facts`

写岗位的人不该各写一遍「数字后面跟不跟单位」。`packing_assistant/post_facts.py` 提供的全是**只做切分、
不做解释**的原语：

| 函数 | 给你 |
| --- | --- |
| `clauses` / `items` | 逗号级 / 句行级切块（千分位逗号不切） |
| `quantities` | 数字 + 单位，**原样**。`HRB400`、`C35`、`Φ20`、`3#楼`、`GB 50010`、`K3+200`、日期里的数字都不算量 |
| `column_quantities` | 一个子句里「哪个数属于哪一列」。长关键词优先（`盘点差` 不是 `盘点`），一个数只用一次 |
| `object_rows` | 一句话里几个对象 → 几行。不带新名字的子句归**前一个**对象，绝不归下一个 |
| `labelled` | `标签：值`、`标签 值`、`标签为值`，行首标签保留其后的逗号；三字以上的标签还认 `责任人刘洋` 这种紧挨着的写法 |
| `person_for` | 带职务的人名（`仓管员张伟`、`王建国（质检员）`）。必须以常见姓氏开头，所以「仓管员今天请假」不会被当成人名 |
| `dates` / `periods` / `deadline` / `clock_times` | 日期、`本周`、`要求 2026-09-26 前` 里的期限、`14:30` |
| `places` / `specs` / `versions` / `doc_codes` | `3#楼`、`B1层`、`5-7轴交C轴`、`K3+200`；`HRB400`、`600×300`；`V2.3`；`CL-017` |
| `table_cell` | 用户的话进表格前的转义（换行、`|`、HTML） |

**铁律**：这一层返回的每个值都是用户原文里的一段**字面文本**。不求和、不换算、不推断、不填默认值。
用户没说的，写手继续留 `TBD` / `待填` / `[A001]` / `UNSPECIFIED`。这条铁律让
`tools/number_provenance` 的数字溯源守卫继续成立——草稿里的每个数都能指回原文。

## 4 改一个岗位

以仓管为参考（`_WH_COLUMNS` / `_parse_wh_rows` / `_warehouse_md`）：

1. 先量：`python scripts/eval_post_content.py --post <岗位> -v`，记下改造前的数。
2. 声明这个岗的**列关键词**（`入库 / 进场 / 到货`…）和**行级标签**（单据号、批次、供应商…），
   用行业词汇，不要抄基准里的句子。
3. `object_rows(text, 列关键词)` 拿到行；每行的 `source` 是它来自的那段原文，用来在行内查标签和人名。
4. 填表时，用户没给的列保持原来的占位符**不变**。
5. 再量一遍；`scripts/test_expert_turn.py` 必须 PASS；空输入和乱输入都要出完整骨架且不崩。

不要做的事：改 `post_facts.py`、改 `_SIMPLE_DRAFTS` 注册表、删改已有的列和免责声明、
在源码里写基准用例的字面量（留出集会专门抓这个）。

## 5 招标三岗（bid-parse / bid-tech / bid-compliance）

这三个岗不在上面两族里：它们背后是文档解析器 `tools/tender_parse.py`，读的是**整行**
（`★…`、`…评分 25 分`），第一个 `N 日历天` 就当工期。人在一个输入框里打字的时候，它是这样的：

| 用户打的 | 改造前 |
| --- | --- |
| `我们投标函先写了999日历天，招标文件要求的工期是60日历天` | 工期 **999** 日历天 |
| `一标段工期180日历天；二标段工期270日历天` | 两个标段都是 180 |
| `正文420日历天；补遗1号改成了450日历天` | 420，补遗被无视 |
| `施工组织设计评分35分。进度计划评分12.5分。`（同一行） | 12.5 分那条**消失**：两句拿到同一个 id `score_L1`，后一个被当重复丢掉 |
| `帮我对下有没有废标点` | 这句指令因为含「废标」二字，成了招标要求，还进了未解决 P0 |

基准上（9 例 67 个事实）：bid-parse 4/24、bid-tech 0/21、bid-compliance 0/22。

### 5.1 字段层 `tools/tender_facts.py`

与 `post_facts` 同一条铁律（每个值都是原文的字面片段），多解决三件招标特有的事：

- **谁的数**——按它在分句里的位置定。一个值默认是招标方的，除非同一分句里它前面站着我方的提示词
  （`我们 / 拟派 / 已转 / 照着写`…）。所以 `工期要求300天投标函照着写的` 既是一条 300 天的要求，
  也是一句关于我方投标函的话。两道保护让粘贴进来的招标文件不被误伤：含 `须 / 不得 / 否决` 的分句
  一律是招标方在说话（`拟派项目经理须具备…`）；`已经 / 还没 / 定了` 这类进度词只在「人在说话」的
  文本里算数，在多行编号条款里不算（`已经取得许可证的，须提供复印件`）。招标方做主语时
  （`招标文件写的是…`）后面的进度词是它的谓语，不是我方。调用方已经知道整段都是招标方原文
  （上传时标了角色的文件）就传 `sides="none"`。
- **哪个标段**——标段一经提到就持续，直到提到另一个标段，或文本说「两个标段都…」。只提到一个
  标段时它是项目的标段，不是拆分。
- **补遗**——补遗只改它点名的那一项，两个值都留着，各自标来源；`补遗没提保证金` 不动原来那行。

显式分块（`招标要求：… / 我方情况：…`，行首、行内、或独占一行当标题）优先于一切提示词，解析器和
字段层读的是同一条规则（`_segments`），所以 `L#` 对两边是同一行。

最后一道网：原话里的每个数字、每个文件编号，要么在某个已归位的值里，要么它所在的分句进
`unplaced` 原样列出。留出集第一轮的 6 个漏项全是「数字从成稿里彻底消失」，加网之后第二轮是 0。

### 5.2 成稿 `tools/tender_tables.py`

按各自 `SKILL.md` 声明的章节和表头出稿——那份说明一直是对的，是代码没跟上：

| 岗 | 表 |
| --- | --- |
| bid-parse | 九节；`事项｜要求原文｜来源页段｜是否检出｜澄清建议`。该问而没有的字段是一行「未在原文检出」+ 去哪查 |
| bid-tech | `评分点原文｜拟写章节｜已有证据｜缺项｜专项接口` + 依据概况 / 工期资源 / 质量 / 点名专项 / 组织机构 / 缺项与自检。没给证据就是 `[A001] 待填`，不编项目名 |
| bid-compliance | `事项｜招标要求｜响应原文或证据｜三态｜缺口｜责任人`，分标段。两边都有数就用响应对照基准已经在量的那套算术比，措辞一律「待人工核验」；`保函还没开` 这种话是缺口；`一级` 对 `二级` 写成「等级字样不同…待人工核验」，不下结论（`二级及以上` 对 `一级` 字样也不同，却是没问题的） |

行首格带标段（`工期（三标段）`），270 天和 285 天不可能被读串。解析器按整行引用要求，而打字的人

的分句（`_quote`）。协作流程里上传的响应文件现在直接回答逐项行：此前是上面一张表写「未响应·
未提供」，下面另附一张对照表写着匹配到的原文和数值冲突，两张表互相打架。

函数名和返回结构没变（`build_workbench_extract_table`、`build_tech_outline_from_handoff`、
`_compliance_gaps_md`），协作流程、网关、MCP 照旧调用。

### 5.5 2026-09-21 补的六项

上一版这里列了六条「还没做的」。逐条：

1. **附件读不出 ≠ 没给。** 以前：CLI 读点名文件时 `except Exception: continue`，扫描件 `投标响应.pdf` 被
   悄悄丢掉，成稿写「用户未提供投标响应资料」、每行「未响应」；扫描件 `招标文件.pdf` 更糟，流程去解析
   点名它的那句话，答「招标协作未完成，请核对资料与输出目录」；工作台上传时 400 拒掉，不留痕迹。
   现在：`office_job.read_material_checked()` 返回 `(正文, "")` 或 `("", 原因)`，原因是我们自己的话，
   从不转述解析器的报错（里面可能带文件字节）；`run_tender_workflow(unreadable=[{title, role, reason}])`
   把它放进带散列的交接，三份稿从交接里读。废标检查多了一个状态 **未能判断·文件未读出**，只用在
   「因为什么都没看到才写未响应」的地方；招标侧的文件（补遗）读不出，写的是「上表招标要求可能不全」。
   招标文件本身读不出：`error_code=tender_unreadable`，点名文件，不写盘。工作台：
   `UploadUnreadable(UploadError)`，照旧整批拒收，但在 `unreadable.jsonl` 里记一行（不是
   `.json/.txt/.bin`——那三种是附件记录本身），上限 24 条，同名文件之后传成功就消掉。
2. **稿件版本。** `tools/bid_check_record.py`（`civil.bid.check.v1`）写在成稿旁边：每份读到的文字的
   sha256（先折叠换行）、每份写出的稿的 sha256、每一行的三态；作业文件另记路径。同一任务再核对一次，
   稿尾多一节「与上次核对相比」：哪个输入的散列变了、哪几行三态变了，别的不列。单岗位把本轮的话按
   「谁说的」拆开散列，`工期改成365天` 显示为我方变了、招标方的话没变。`civil review <稿>` 找到记录后
   重算成稿散列、按当时的读法重读作业文件，逐个报 未变 / 已改动 / 找不到；打字或附件当时的文字无法
   重读，就说无法重读，绝不报成「未变」；核对过期则 review 不干净。散列只说「是不是同一段文字」，
   不说哪一版该递交，稿里也这么写。
3. **证据文件。** 声明了招标文件之后，`reference` 角色的文件（绝不包括用户本轮打的字）被逐字搜索
   我方在证据类行上写的值——人名、证书等级、编号、金额；搜索前折叠空白和冒号（PDF 文字层会把名字
   拆成 `李 明`）。结果在第 8 节「证据文件字样核对」逐词列出；没搜到的词写进该行的缺口和第 7 节。
   报的只是**字样出现与否**，不是证件真伪、是否在有效期、是否本人；证据文件里有读不出的（证书多半是
   扫描件），答案是「未能判断」而不是「未检出」——只有一种情况例外：文件名说的就是这一行（`项目经理证书.pdf`）、
   读到了、里面却没有我方写的那个名字，这时直说「未检出」，不因为别的文件没读出来而含糊（这是读真实成稿时
   发现的：证书上是王强，我方写的李明，一份无关的扫描件却让结论变成了「未能判断」）。行的三态不因此改变：缺一个词是待补的缺口，不是结论。
4. **英文条款**、5. **项目名称**、6. **项目经理之外的人**：字段层。英文别名按词匹配、不分大小写；
   `we / our` 是我方提示词，且排在 `shall` 之前（`We shall complete…` 是我方）；项目名多认了几种写法，
   认不出仍然留空不猜；点了岗位的人名进 `staff`，行名就是用户写的岗位。留出第四轮量的就是这三项（5.3）。

顺带发现并改掉的：废标检查稿里的「未解决 P0：N 项」是全稿唯一一个 `civil review` 找不到出处的数——
工具自己数出来的。现在逐项列出，不写总数。

### 5.6 还没做的

- **OCR 没有做。** 读不出的文件现在会被说出来，但还是读不出；扫描版证书在证据核对里永远是「未能判断」。
- **证据核对只是字样。** 同名的另一个人、过期的证书、PS 过的扫描件，它都分不出来。
- **Rust 工作台**（`workbench/src/attach.rs`）有自己的一套上传提取，拒收读不出的文件时不写
  `unreadable.jsonl`；只有 FastAPI 这条路记。
- **工作台上无法撤销一条「未读出」记录**：换了名字重传（`投标文件-ocr.pdf`）之后，旧名字那一条还会
  被报出来，相关行会偏保守地标成「未能判断」。同名重传才会消掉。
- **单岗位路径没有证据文件这个概念**：点名的文件被拼成一段文字一起读，不分角色；证据核对只在带角色
  的协作流程里有。单岗位的核对记录里，输入也只有「本轮的话」，没有逐个文件的散列。
- **没有字段词的数**（`We have stated 17 months in our Form of Tender`）不归任何字段，只进兜底网。
- **辖区**：`S$`、HDB 这类信号不足以让 `infer_jurisdiction` 判 SG（规矩是没写明就不默认国家），英文
  招标如果不出现 BCA / Singapore 字样，辖区一栏仍是 UNSPECIFIED。
- 英文人名只在「该出现人名的位置」（责任人、拟派人员）认，且必须是 2–4 个首字母大写的词；
  `bin / s/o` 这类写法不认。
