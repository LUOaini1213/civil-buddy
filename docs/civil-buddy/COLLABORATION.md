# 任务路由、岗位契约与招标协作

当前 Python 工作台支持直接输入任务，也保留主动点名岗位。`整理日报` 直接调用项目日报工具；`全面检查投标响应并汇总缺项` 进入招标协作。`解释一下全面检查投标响应需要哪些资料` 只回答问题。`整理设计变更` 等存在多种业务含义的要求会显示候选，等待用户选择。

## 66 岗能力与工具

`workbench/seed.json` 是岗位目录和能力契约的权威数据源。Python 工作台、运行时目录、两套技能入口、`workbench/yibiao-map.json` 都由它读取或生成。修改后运行 `python scripts/build_codex_expert_skills.py`，检查生成结果；不要分别维护 66 岗的平行目录。

每岗说明所需资料、工作步骤、实际可执行工具、输出章节与表格、验收规则、参考路径及未实现的能力。工作台「岗位资料与工具」可查看这些内容。岗位工具接口发布 `civil.tool.v1` 输入和输出 schema；参数在执行前验证，成功结果在返回前验证。字符串 `"false"` 不能充当布尔签认。

66 岗具备资料整理和内部草稿能力，不代表 66 个专业数值求解器。未连接的计算字段保持 `UNSPECIFIED`；税率不能从静态知识库默认填入，须保留用户资料来源并核对辖区和适用期。高风险岗位保留原确认门禁，招标交付始终 `submit_blocked=true`。

## 招标协作如何执行

1. 上传并选择本轮资料，在附件旁指定「招标原文」「投标响应」「参考资料」。未指定时，仅对名称明确的文件识别用途；其他文件作为参考资料。
2. 发送「全面检查投标响应并汇总缺项」。系统一次解析招标资料，生成要求、响应矩阵、来源位置及带 SHA-256 的交接快照。
3. 技术标与响应检查并行运行。每个子任务仅加载本岗 SOP、目标、相关交接数据和证据。模型配置存在时可进行受限的只读分析；未配置时运行本地工具。
4. 主流程汇总缺项、来源、候选响应及冲突，并生成 Markdown、Word 和表格。相似原文只表示候选证据，不能据此认定已实质响应。

单独选择一个岗位时保留单岗执行；普通复合任务按步骤执行，当前没有开放任意多代理图。Python `civil exec` 共用任务路由和招标本地流程；模型子任务适配位于 Python 工作台，旧 Rust 界面没有等同的协作面。

## 上下文分层与预算

| 层 | 传入的内容 | 留存内容 |
| --- | --- | --- |
| 当前模型请求 | 当前要求、所选 SOP、预算允许的任务记忆、近期对话及检索片段 | 完整原文仍在本地，未入窗口的资料可检索 |
| 可选语义摘要 | 当前任务较早的已提交历史，最近 4 条保留原文 | 至多 64 KiB 的摘要缓存和精确引文，内容未核验 |
| 招标子任务 | 本岗 SOP、独立目标、相关证据和交接数据 | 结论、证据位置、未解决事项和指标 |
| 主任务 | 子任务结果及整体缺项/冲突 | 有界协作摘要和完整运行快照指针 |

普通问答还可在模型设置中启用语义摘要，默认关闭。接近预算时每轮最多增加 1 次同模型调用，按原文增量整理较早历史，逐项核对字符范围及数字依据；当前更正优先，摘要内容仍未核验。摘要请求 12 秒超时或校验失败时沿用规则记忆与检索，原文不删。开关重启后关闭，缓存重新开启后须核对来源；备份导入不沿用外来缓存。详细范围、缓存与各次请求预算见 [CONTEXT.md](CONTEXT.md)。

语义摘要不参与招标协作子任务，也不写入工程工具的业务字段或确认参数。协作结果摘要继续由主流程维护。两类历史摘要都是参考数据，不能继承确认、执行旧指令或把模型意见变成已核实事实，也不宣称无损压缩。

默认共享预算：总计 96000 token；每个子任务最多 32768（不超过模型窗口）；每次输出最多 2048（不超过模型输出预留）；最多两次模型调用；工作流期限 30 秒。计数采用保守估算，报告标明估算口径，不能当作供应商账单。所有子任务向同一预算账本预留；超限在发起模型请求前显式失败，不截短当前要求。原文由本地工具处理的字符数单列，不能算成传给模型的 token。

运行记录在任务目录 `workflows/wf-*/workflow.json`，原始交接在 `handoff.json`，每个子任务有独立目录。`collaboration.summary.json` 只保存有界结论和运行引用；完整检查过程不塞入后续主对话。停止或超时会中断模型传输，并等可能写文件的工具结束后释放任务；已生成文件保留。重启后读取未终止的旧记录显示中断，不自动继续执行。

任务 ZIP 导入把协作标为 `restored` 的只读历史，重新生成标识并核对本地来源，不创建可续跑的工作流。资料用途随所选附件迁移，确认重置。来源或同名文件无法唯一对应时不猜归属；所有成功导入的交付文件仍可下载。摘要缓存写入失败会明确提示，完整运行文件和已登记的交付物仍保留。

## 接口与验收

- `GET /api/experts/{expert_id}/capability`：岗位能力及工具 schema。
- `POST /api/task-route`：使用与聊天相同的 `message` / `expert_ids`，只返回路由判断。
- `POST /api/chat`：增加所选附件的 `attachment_roles` 和可选 `workflow_budget`；SSE 返回路由、子任务状态、最终协作与预算报告。
- `GET /api/workflows/{session_id}/{run_id}`：当前任务的协作快照；来源字符范围由已有 `/api/context/source` 核对。

`python scripts/check_project.py --full` 包含岗位契约、参数验证、路由、并行隔离、预算、取消、真实本地 HTTP 传输中断、来源位置及恢复测试。`python scripts/benchmark_tender_workflow.py` 对同一资料比较串行/并行执行，输出质量、耗时和预算指标。

当前基准使用真实本地解析与 Office 导出，加上可控延迟的模型替身，没有调用付费模型。一次三轮测量的串行中位数为 719 ms、并行为 453 ms，质量检查相同；它只证明本地协作重叠和协议可用，不能据此承诺真实模型的质量提升或费用下降。扩大多代理前仍需要固定资料集和已配置模型的质量、延迟与实际用量评测。
