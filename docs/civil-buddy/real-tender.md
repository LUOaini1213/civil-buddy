# 拿真实招标文件来用：招标三岗的用法、量过的数、不能指望它的地方

这份文档写给投标的人。三个岗位——招标解析（bid-parse）、技术标目录（bid-tech）、废标检查（bid-compliance）——
**不调用任何模型，不联网**：读文件、抽字段、逐条列条款、对数字，全是确定性的程序。成稿里每个值都是原文里的一段字，
每一行都标着它在招标文件里的位置（`第二章 前附表 3.4.1（第12页）`）。它不替你判断能不能投、会不会废标。

## 1 三步

```bash
pip install -e .            # 得到 civil 命令；要读扫描件再加 .[ocr]
cd 某个投标项目的文件夹       # 招标文件、我方的投标函/施组/报价表、证书，都放这里
civil init                   # 写一份 CIVIL.md（项目名、辖区；留空的保持 UNSPECIFIED）
```

**第一步，解析招标文件**（Word、带文字层的 PDF、或扫描件 + OCR 组件）：

```bash
civil exec "解析招标 招标文件.pdf"
```

得到 `tender.parse.md`（同名 Word / Excel 一并导出）：项目与公告、时间轴、资格与业绩、实质性响应、评分点、限价、
点名的危大专项、保证金；文件是「八章 + 前附表」那种结构时，再多三节——**形式签章与递交要求**、
**否决与拒收条款（逐条，一句一行，带条款号）**、**投标文件组成清单**。

**第二步，核对我方文件**（文件名里带「招标 / tender」的是招标文件，带「投标 / 响应 / bid」的是我方文件，其余当证据文件）：

```bash
civil exec "全面检查投标响应：招标文件.pdf 投标函.docx 投标文件-施工组织设计.docx 投标文件-报价一览表.docx 项目经理证书.pdf"
```

得到 `bid-compliance.md`：

| 节 | 内容 |
| --- | --- |
| 3–5 | 每个字段一行：招标要求 ｜ **我方每份文件里写的值（带文件名）** ｜ 三态 ｜ 缺口。每个值都跟招标要求比：`560日历天（施工组织设计.docx）` 超过 `540日历天` → `未响应·数值不符`，并点名是哪份文件 |
| 6 | 招标文件点名的危大专项、每个评分项，在我方文件里**有没有这几个字**（只查字样，不评章节好坏） |
| 8 | 证据文件字样核对：我方写的人名、证书等级、编号、金额，在证书/保函文件里出现没有。文件名说的就是这一项、读到了却没有这个名字 → 直说「未检出」 |
| 9 | **投标文件内部一致性**：同一个字段在我方几份文件里有两种写法（投标函 540 天、施组 560 天；周建国 / 周建华）。同一金额一处写万元一处写元不算不一致 |
| 10 | 否决与拒收条款自查清单：每条带出处和一个空框，人工逐条打勾 |
| 1 | 这次核对读了哪些文件、各自的 sha256 前 12 位 |

**第三步，递交前再核一遍**：改过任何文件之后重跑第二步，稿尾会多一节「与上次核对相比」——哪个文件变了、哪几行三态变了。
`civil review bid-compliance.md` 会告诉你这份核对稿是不是还对得上现在的文件：文件改过、稿子被手改过，都会报出来。

## 3 不能指望它的地方

- **否决条款要看两张表。** 清单（第 11 节上半）认一套固定说法；它下面的「弱信号」表宁可多列，收的是说法不在词表里、但可能同样致命的句子。在没见过的用词上，清单本身只抓到过 4/18，两张表合起来 16/18。两张都要过一遍。
- **否决条款清单不保证全。** 它抓的是含「否决 / 不予受理 / 拒收 / 无效投标 / ★ …」字样的句子，以及这种句子领起的分条清单。
  换一种它没见过的说法就会漏。清单是帮你少翻几遍文件，**不是免读声明**：评标办法和投标人须知两章必须有人通读。
- **字段取自前附表。** 没有前附表、或者前附表的行名它不认识的文件，字段会空着（写「未在原文检出」），不会去正文里猜。
  没见过的真实文件上字段首跑只有一半（见上表）：成稿里「未检出」的行，请到原文前附表里核一遍。
- **多标段 / 多包**：公告里的标段表、前附表里「一标段：…；二标段：…」、分标段写的资格要求，按标段分行列出。标段写法太怪（不含
  「标段 / 包」字样）认不出来。**这份文件是哪个标段的**它不判断。
- **补遗、澄清、更正公告**：和招标文件一起点名（`解析招标 招标文件.pdf 补遗书第1号.pdf`），文件名里要带「补遗 / 澄清 / 答疑 / 更正」。
  认的是「由 A 调整为 B」「修改为」「变更为」「延期至」和答疑里直接回答的句子；改动那一行标「以补遗为准」，原来那一行标「已被…修改」。
  补遗里整段替换条款、或者只说「详见附件」的，它读不出来——**补遗必须有人通读**。
- **英文招标文件**：SECTION / PART 分章、Instructions to Tenderers 后面的 Appendix 或 Bid Data Sheet 当前附表、百分比权重当评分项。
  留出的那份首跑是 0/12（见上表），修过之后只在两份合成文件上验证过，**没有跑过真实的英文招标文件**。
- **Word 自动编号**能还原（条款号是列表编号的情况），但靠「样式」带出来的编号读不到，那种条款的定位只到章。
- **PDF**：表格按页面上**画出来的表格线**还原（Word 导出的 PDF 都是这种）；水印、页眉、连续递增的页码会去掉；跨页的表合成一张，
  被分页切开的一行接回去；表中表按内层的行展开；两栏排版的正文按栏读。没有表格线的表（用空格对齐的）、竖排、旋转 90° 的页
  还原不了，退回纯文字；成稿里每行都有页码，拿不准就翻到那一页看原文。
- **扫描件**要装 OCR 组件（`pip install -e .[ocr]`，RapidOCR + pdfium，本机运行，不联网）。OCR 会认错字，数字错了也看不出来
  （竣工→峻工、；→：）。由 OCR 得到的成稿顶上有一行加粗的警告：**每个数字都要翻到标注的那一页对照原件**。
  一百页的扫描件要读十分钟上下（CPU），读过一次会缓存。
- **证据核对只查字样。** 同名的另一个人、过期的证书、改过的扫描件，它都分不出来。
- **我方文件只读这几样**：工期、投标有效期、缺陷责任期/质保期、投标保证金、投标总报价、质量标准、项目经理、技术负责人、
  项目名称、招标编号。资质、业绩这类要看证书原件的，它只会告诉你「我方文件里没读到」。
- **它不判断**：不说「可以投标」「不会废标」「资格审查通过」。三态只描述「给没给、对不对得上」。
- 工作台（网页）上传的附件单个最多读 20 万字，超出会在成稿里写明「文件没有读完」；命令行单个文件读到 200 万字。
  扫描件上传时走 OCR（装了 OCR 组件才有），一次最多识别前 40 页，超出的会写明；更长的扫描件放进作业文件夹用命令行解析。
- **从网址取文件**（工作台输入框旁的「网址」）：工作台自己去取，取回来和上传的附件走同一条路。只取 http(s) 的**公网**地址
  （域名解析到本机、内网、云元数据地址的一律拒绝，每一次重定向都重查），单个 20 MB 以内，网页只留文字。要登录、要验证码、
  要点「同意」才给下载的站点取不到——那种请自己下载后上传。

## 4 数据

三个岗位不调用模型、不发任何网络请求（只有你在工作台里点「网址」时，工作台才去取你给的那一个地址）；文件只在你的文件夹里读，成稿写在 `<文件夹>/.civil-buddy/out/`。
核对记录（`check.json`）里存的是文件的 sha256 和各行三态，不存文件内容。OCR 的识别结果缓存在
`<文件夹>/.civil-buddy/cache/ocr/`，删掉即可重读。

## 5 免责

本工具的成稿是内部讨论用的草稿，`submit_blocked=true`：不构成投标文件，不代替对招标文件的通读，不代替持证人员的判断。
