# 任务记忆、上下文预算与本地检索

Python 工作台（`civil app`）在每次发送时组合当前要求、岗位 SOP、任务记忆、相关原文和近期对话。所有来源都来自本任务的本地资料；问答模型仍由用户在模型设置中选择。

## 怎么使用

1. 持续使用同一个任务。输入框下方显示上一次完整模型请求的占用、压缩情况和找回段数；编辑文字时不会把浏览器展示的历史误报为完整模型请求。
2. 点击「任务记忆与本地搜索」，查看从已提交消息提取的目标、明确字段、约束、决定、待办和结果线索。`项目名称：…`、`截止日期：…` 等明确字段便于准确记录；同一字段的更正保留新值和来源。
3. 输入原文关键词进行本地搜索。历史对话始终限于当前任务；附件只有当前选择的文件可被检索并用于问答。点击「查看原文」核对来源字符范围。
4. 在模型设置中填写供应商支持的上下文上限和回答预留。默认分别为 32768 / 4096 token，属于保守配置，不能自动探测供应商的真实窗口。进程设置重启后恢复；长期设置使用 `CIVIL_CONTEXT_LIMIT` / `CIVIL_CONTEXT_RESERVE`。
5. 可选：在模型设置中勾选「长对话自动生成语义摘要」并保存。默认关闭，保存本身不调用模型；只有配置模型的问答接近预算时才可能新增摘要。输入框下方显示后端报告的状态、调用次数及 token 预算估算；「任务记忆与本地搜索」会在规则记忆后显示「模型语义摘要（未核验）」。
6. 单任务 ZIP 备份保留完整对话和原始附件。导入新任务后重建规则记忆与检索索引，并重置签认，不复制旧任务的索引地址或执行权限，也不信任或沿用外来语义摘要缓存。协作结果作为只读历史记录导入，附件用途和可核对的来源重新关联到新任务；不自动恢复执行。
7. 摘要不准确或本地搜索异常时，点击「重新整理记忆」。它会撤回当前任务的模型摘要，从已保存的完整原文重建规则记忆和搜索，不调用模型。原始对话、附件、交付物、工程槽和既有运行记录保留；语义摘要开关也保持原值。

无需 API Key、向量模型或额外服务即可保存记忆、搜索和核对原文。配置问答模型后，只有本次预算允许的记忆、历史和检索片段会加入请求；模型生成回答时仍会调用所配置的 API。来源卡表示提供给模型的参考资料，不等于模型逐条核验了它们。

## 可选模型语义摘要

语义摘要仅作用于已配置模型的普通问答，不进入确定性工具的业务字段，也不参与确认或招标协作子任务。每轮最多增加 1 次同模型摘要调用；未启用、无 Key、无需压缩或没有合适的历史片段时，不增加该调用。当前问题仍单独保留，出现当前字段更正或明确纠正时，本轮不加载旧语义摘要，以当前原文和规则记忆为准。

摘要输入只取当前任务服务端已提交历史的较早部分，不包含浏览器补传历史、其他任务或原始附件；最近 4 条已提交消息保留原文，不作为摘要候选。处理按消息与字符位置增量推进，每次从原文取资料，不把旧摘要交给模型继续改写。单条长消息也可能分批处理，不能把“已摘要”理解为覆盖全部历史。

模型返回的每项内容必须引用本次提供的消息 ID、精确 Unicode 字符范围及完全一致的引文；摘要数字必须在该项引文中出现，而且引文不能截断原文中的完整数值，例如不能把“12”中的“1”当成独立数值。跨分块、负号、小数和指数同样检查。无效来源、无依据数字、签认或授权内容不能通过校验。这只能核对来源和结构，不能证明模型改写在语义上正确；用户事实、助手结果与摘要内容仍须核验。页面提供原文入口，来源链接最多展示最近 12 处，其余位置保留在摘要中。

摘要请求的输入预算为当前可用窗口的三分之一、最多 8192 token，输出预留最多 1024 token 且不超过模型设置的回答预留。摘要请求与后续各个回答请求分别检查完整输入和输出预留；报告同时记录本轮调用与合计预留的估算，不是账单或实际费用。摘要被裁减、覆盖不完整或未能进入回答窗口时，不据此宣称旧原文已被完整替代。

摘要模型调用有 12 秒期限。超时、返回格式或证据校验失败、写入失败时，继续使用规则记忆和检索；已有缓存也只有重新核对来源后才可能使用。相同资料失败后短时间内暂缓重试，当前为 60 秒。取消后迟到的摘要不写入缓存。原文始终保留；缺失或旧版本已截掉的内容不能恢复。

开关只在当前进程有效，重启或「恢复启动配置」后关闭。`semantic.summary.json` 缓存上限为 64 KiB（65536 字节），旧摘要片段可能被移出缓存，但不会删除原文。重启后的缓存先留在磁盘，重新开启后须核对当前任务标识、历史前缀和每条来源才能复用；来源或历史有变时，不把旧缓存当成可信事实。任务备份导入只凭导入后的原文重建派生记忆与索引，需要语义摘要时再按开关和预算重新生成。

同字段重填新值的失效检测直接扫描原文，不受规则摘录的 4000 字符上限影响。超长目标或约束的新值仍可使旧摘要失效；这不表示长段文字已完整进入规则记忆。

## 重新整理记忆

页面分别说明规则记忆是否可读、模型摘要是关闭、尚未生成、可用还是失效。派生缓存读取失败不会阻断任务详情的恢复；原始文件损坏仍需先核对或从备份恢复。

重新整理只处理当前任务的派生文件，清除模型摘要、失败重试记录和旧请求统计，并重新建立原文搜索。进行中会阻止本页面重复操作及发送新消息；其他正在处理同一任务的请求会得到冲突提示。只读模式和无写权限时不会开始重建。页面切换任务后，旧重建、读取或搜索响应不能覆盖新任务的内容。

原始对话包含损坏记录时，重建会明确停止，不把剩余有效行当作完整资料。附件元数据损坏、原件或提取文本缺失，以及文件大小或文本长度与记录不符，也会在更新索引前停止，保留上一次索引供核对。缓存路径若被文件夹或链接占用，也不会删除其内容。遇到磁盘满或文件被占用，重建可能只更新了部分派生缓存，界面会报告失败，可排除问题后再次执行；原始资料不会修改。成功后不会立刻调用模型，后续问答是否重新生成摘要仍由开关与预算决定。

## 数据与边界

| 数据 | 位置与用途 |
| --- | --- |
| 完整对话 | 任务目录 `transcript.jsonl`，每条包含稳定 ID；浏览器近期 200 条、单条 8000 字节的节选只影响展示 |
| 可重建记忆 | `context.summary.json`，提取项带消息 ID、字符范围与原文，保留显式字段的被替代版本 |
| 可选语义摘要 | `semantic.summary.json`，有界的模型历史改写与精确引文；默认不启用，全部标为未核验 |
| 本地索引 | `local-retrieval.sqlite3`，SQLite FTS5 分块检索，中文词片段、BM25 与关键词覆盖排序；不是语义向量检索 |
| 最近请求统计 | `context.last.json`；各运行审计记录同时记录上下文预算 |
| 工程会话槽 | 原有 `session.summary.json` 的项目、辖区等槽位继续单独维护，不充当用户画像 |
| 协作记忆 | `collaboration.summary.json`，保存有界的子任务结论、未解决事项和完整运行引用；不保存子任务长对话 |

计数使用已有本地 tokenizer 加余量，缺少缓存时按 UTF-8 字节保守估算，不会为了 tokenizer 下载文件。它是预算估算，不能保证等于任何供应商的精确 token 数。系统提示、所选岗位 SOP、工具 schema、记忆、检索材料、历史、当前输入与回答预留共同受限；当前要求和必要系统内容过大时，在调用模型前明确报错，不静默截短当前要求。较早原文退出模型窗口后仍可从本机找回。

规则记忆和可选语义摘要都不是无损压缩。长段落、不明确的更正和同义改写可能需要原文检索；检索结果不是全文阅读，未入请求的来源会在预算报告中标明。已有旧版本写入时被截掉的内容无法凭空恢复。

招标协作进一步隔离子任务上下文：各子任务只拿相关技能、目标和证据，主任务只接收结论、证据位置与未解决事项。所有子任务共用总预算，同时限制单次窗口、输出长度、调用次数和期限。该协作摘要与普通问答的可选语义摘要分别维护；详细协议、恢复与评测见 [协作说明](COLLABORATION.md)。

附件仍遵循原有解析边界：每文件 20 MB、每任务 12 个、单次上传 25 MB，提取文本最多 200000 字符；扫描 PDF 不提供 OCR。索引只覆盖实际提取出来的文字。原件仍保留，超过提取范围的资料应拆分后上传。

交给本地岗位工具的起草资料按字符计，与问答模型的 token 预算无关：所选附件的开头每个最多 20000 字、合计不超过 60000 字（`uploads.INJECT_CHARS`）；连同检索命中的附件片段和沿用的此前用户资料，整份资料不超过 240000 字（`session_context.MATERIAL_CHARS`）。本轮用户要求始终完整并排在最后。放不下的附件片段整段不加入，此前用户资料只保留最新的连续几条；未加入的内容在资料末尾用一行列出，并显示在输入框下方的上下文说明中。

历史事实不能触发写入，历史确认不产生本轮授权，助手以前的完成说法只记为未核验线索。当前用户的显式更正优先。高风险岗位仍须本轮确认，`submit_blocked=true` 不变。

## 本地接口与验证

- `GET /api/context?session_id=…`：读取任务记忆和最近请求报告；启用且缓存校验通过时返回 `semantic_memory_text`，否则为空字符串。`memory_status` 与 `semantic_status` 提供当前状态及可读说明，区别于上一次模型请求的统计。
- `POST /api/context/rebuild`：严格接收 `{session_id}`，返回重建后的上述详情及 `rebuild` 计数；不调用模型或业务工具。任务忙为 409，只读或权限不足为 403，任务/原文不存在为 404，参数或资料无效为 400/422，存储失败为 500。
- `POST /api/context/search`：`{session_id, query, attachments:[id]}`；省略附件只搜历史。
- `GET /api/context/source?session_id=…&source_id=…&start=…&end=…`：读取匹配原文。范围为 Unicode 字符的左闭右开区间，单次最多 20000 字符。
- `POST /api/llm-config` 接受严格整数 `context_limit`、`output_reserve` 和严格布尔 `semantic_summary`。开关省略时保留当前值；字符串、数字和 `null` 不能代替布尔值。所有字段先校验，无效提交不会先更改模型或预算；`clear: true` 关闭语义摘要并恢复启动配置。
- SSE `context.semantic` 返回状态、后端说明、调用次数、输入与输出预留及覆盖情况。页面按报告展示；token 计数与预留为预算估算，不提供精确计费承诺。

运行 `python scripts/check_project.py --full`，覆盖存储、检索、提取记忆、完整请求预算、HTTP 流程、页面交互和既有工程工具。回归场景包含早于 200 条的事实、长消息后半段、附件尾部、跨任务隔离、未选择附件排除、重启与备份恢复、当前输入超限及历史确认失效。
