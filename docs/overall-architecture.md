# 完整架构（最终版）

面向：远东新加坡陆路交通局办公楼项目 · 钢结构件  

**两阶段之间必须有用户确认**（Human-in-the-loop）。

接口字段见 [`api-spec.md`](./api-spec.md)。

## 一、总体架构图

```
用户输入（材料清单）
          ↓
    【主控智能体】
          ↓
┌─────────────────────────────────────────┐
│     【团队A】装箱方案智能体团队            │
│                                         │
│  · 材料解析智能体                        │
│  · 结构计算智能体                        │
│  · 装箱方案智能体                        │
└─────────────────────────────────────────┘
          ↓
   输出给用户：完整装箱方案
          ↓
┌─────────────────────────────────────────┐
│           【用户确认环节】★ 必须          │
│                                         │
│  · 查看装箱方案                          │
│  · 确认 / 指定集装箱类型                 │
│  · 可提出调整需求                        │
└─────────────────────────────────────────┘
          ↓ 用户确认后
┌─────────────────────────────────────────┐
│     【团队B】拼柜方案智能体团队            │
│                                         │
│  · 规划智能体                            │
│  · 装载执行智能体（skjolber）             │
│  · 评估优化智能体                        │
│  · 风险合规智能体                        │
│  · 可视化智能体（三视角图）               │
└─────────────────────────────────────────┘
          ↓
   输出给用户：拼柜方案 + 风险报告 + 三视角图
```

## 二、智能体完整列表（共 9 个业务智能体）

| 层级 | 名称 | 职责 |
|------|------|------|
| **1 主控** | 主控智能体 | **开头选柜** + 意图/名册/双利用率目标/二层堆码策略；**结尾复核柜型**（finalize） |
| **团队A** | 2 材料解析智能体 | 解析材料清单，标准化数据 |
| | 3 结构计算智能体 | 推荐箱型约束与加固建议（成箱后半严格校核） |
| | 4 装箱方案智能体 | 合箱 + 结构计算，生成木箱/铁架（展示名按外长） |
| **用户确认** | — | **人工确认柜型或提出新需求（必须环节）** |
| **团队B** | 5 规划智能体 | 装载策略：长度优先 + 并排占底 + 吃重 |
| | 6 装载执行智能体 | 3D 装载（skjolber 或 python-laff-3d） |
| | 7 评估优化智能体 | **空间子分 + 重量子分 + 综合分** |
| | 8 风险合规智能体 | 偏心/超重/双低利用率等规则 + 可选 LLM |
| | 9 可视化智能体 | 俯视、侧视、正视三视角 |

> 另有 `present_team_a`（确认闸门）与 `finalize`（主控汇总输出），不计入 9 智能体业务编号。

## 三、核心流程说明

1. 用户提交材料清单  
2. 主控启动 **团队A**，完成装箱方案  
3. 将装箱方案展示给用户（见 [`team-a-user-output-template.md`](./team-a-user-output-template.md)）  
4. **用户必须确认**（选择集装箱类型，或提出调整）  
5. 主控再启动 **团队B**，完成拼柜、风险、可视化  
6. 输出最终完整结果  

**主控状态机（简）**

```
IDLE → TEAM_A_RUNNING → AWAIT_USER_CONFIRM
         ↓ 用户调整装箱
       TEAM_A_RUNNING（重跑）
         ↓ 用户确认 + container_type
       TEAM_B_RUNNING → DONE
```

未确认前 **禁止** 调用团队B / skjolber。

## 四、技术分工

| 范围 | 建议 |
|------|------|
| 主控 | LangGraph / 状态机；挂起等待用户确认（interrupt / 会话状态） |
| 团队A | Python 优先 |
| 团队B | Java Spring Boot；装载核心 **skjolber** |
| 可视化 | 结构化 `views` → Vue2 三视角 |
