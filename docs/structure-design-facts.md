# 详设结构事实 + 自然语言改方案

## 为什么

默认截面半严格筛查 **不能** 当详设事实。  
正式结构结论必须绑定：**截面型号、γ、吊点、图纸号** 等可追溯输入。

## 详设怎么提供

### 1）文件（推荐）

复制示例并改成项目真实数据：

```text
knowledge/structure_design_facts.example.json
  → knowledge/structure_design_facts.json
```

或环境变量：

```text
STRUCTURE_DESIGN_FACTS_PATH=路径/structure_design_facts.json
```

### 2）API 注入

`POST /api/team-a` 带 `design_facts` 对象（与 JSON 同结构）。

### 3）自然语言

`POST /api/revise-nl` 或网页「自然语言改方案」：

```text
框架用槽钢16#，底板槽钢14#3根，γ=2.0，图纸ST-4M-001
柜型改成40GP；去掉钢梁
```

系统会写入 `design_facts` 并 **重跑团队A** 结构校核。

## 结论语义

| 结论 | 含义 |
|------|------|
| **通过** | 在当前截面/γ 下校核通过（有详设时 = detailed_design） |
| **需加强** | 软项不足，可讨论但要加固 |
| **待详设** | **无详设事实**，禁止当正式出运结构依据 |
| **不通过** | 硬项失败或详设截面解析失败 |

风险合规：`待详设` / `不通过` 均会 **REJECT** 阻断出运。

## 校核仍说明

即使有详设截面，力学模型仍是 **半严格**（简支梁/轴压长细比等），不是完整 FEA。  
**详设事实** 保证「用的是项目截面与参数」，不是「自动等于签章计算书」。

## 自然语言支持的操作

| 说法 | 动作 |
|------|------|
| 去掉/删除 XXX | 滤材料 |
| 柜型 40HQ/40GP… | 改柜型 |
| 框架用槽钢16# | 详设框架截面 |
| 底板槽钢14#3根 | 详设底梁 |
| γ=2.0 | 安全系数 |
| 图纸 ST-xxx | 图号 |
| 强制 4米铁架 | packing force_box_type |
